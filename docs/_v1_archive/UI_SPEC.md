# Master Mentor — UI Specification

## Design principles

- Desktop-first.
- One clear next action.
- No noisy dashboards.
- Always show why a mentor recommendation exists.
- Use visual hierarchy for Critical > High > Medium > Low.
- Do not use color as the only indicator.

## Main navigation

1. Today
2. Dashboard
3. DSA
4. Skills
5. Revision
6. System Design
7. CS Fundamentals
8. Practical Engineering
9. Behavioral
10. Mocks
11. Weekly Review
12. Roadmap
13. Settings

## Today page

Primary content:

### Readiness
- score
- component scores
- target date

### Today's Mission
Show 3–6 tasks.

Each task:
- title
- estimated minutes
- target skill
- priority
- reason
- start action

### Due Revision
Show overdue first.

### Mentor message
One concise recommendation.

Example:

> Do not start DP today. Your Graph pattern-recognition score is still below threshold.

## Dashboard

Show:

- readiness trend
- skill matrix
- top gaps
- recent evidence
- revision health
- mock trend

## DSA

Views:
- patterns
- problems
- attempts
- weak areas

Problem logging should require minimal clicks.

## Skill detail

Show:

- skill score
- target
- gap
- confidence
- evidence history
- related skills
- prerequisites
- recent failures
- revision status
- next recommended mission

## Revision

Tabs:
- due
- overdue
- upcoming
- completed

## System Design

For every exercise:
- problem
- requirements
- scale assumptions
- architecture notes
- trade-offs
- score
- weaknesses
- next revision

## Mocks

Show:
- recent mocks
- score trend
- dimension scores
- repeated weaknesses

## Weekly review

Sections:
1. What improved
2. What regressed
3. Revision completion
4. Top gaps
5. Next week priorities
6. Readiness change

## Responsive requirements

Must remain usable at:
- 1280x720
- 1440x900
- 1920x1080

Mobile support is secondary for MVP.
